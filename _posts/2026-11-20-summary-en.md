### [PHP URL Capitalization Vulnerability Fixed After 20 Years](https://x.com/ljachowicz/status/2123477025268924514) ⭐️ 8.0/10

PHP has fixed a critical 20-year-old vulnerability where capitalizing the &\#x27;s&\#x27; in URLs \(httpS://\) causes PHP to disable TLS encryption, exposing sensitive information like tokens, credentials, and request data. The issue \(CVE-2026-128064, CVSS 4.0 score 8.2\) has been resolved in PHP versions 8.2.36, 8.3.37, 8.4.28, 8.5.13, and 8.6.0, while PHP 8.1 and earlier versions remain vulnerable as they are end-of-life.

telegram · zaihuapd · Nov 20, 03:04

**「Background」** PHP&\#x27;s stream wrappers handle URL schemes in a case-insensitive manner, but historically only enabled TLS encryption when the fifth character of the scheme was a lowercase &\#x27;s&\#x27;. This meant that URLs like &\#x27;httpS://&\#x27; or &\#x27;HTTPS://&\#x27; were treated as unencrypted HTTP connections instead of secure HTTPS connections, exposing sensitive data in transit. The vulnerability remained undetected for 20 years due to PHP&\#x27;s case-insensitive URL scheme parsing combined with the specific position requirement for the lowercase &\#x27;s&\#x27; to activate TLS.

**「Security Impact」** Developers and organizations using PHP versions 8.1 and earlier \(end-of-life\) or unpatched versions are vulnerable to having sensitive information exposed when URLs with capitalized schemes \(httpS\) are used, potentially leading to token theft, credential exposure, and other security breaches. Organizations must upgrade to patched versions \(8.2.36, 8.3.37, 8.4.28, 8.5.13, or 8.6.0\) or ensure URL schemes are consistently lowercase in their applications.

### [Inkling 2 Mini: vLLM&\#x27;s Day-0 Support for Looped Models](https://vllm.ai/blog/2026-11-20-inkling2-mini) ⭐️ 8.0/10

rss · vLLM Blog · Nov 20, 00:00

**「Background」** Inkling 2 Mini is a novel looped model architecture where middle layers run multiple times with shared weights, each maintaining its own KV cache. vLLM now supports this complex architecture on day 0 across NVIDIA Blackwell, Hopper and DGX Spark platforms.

**「Solution」** vLLM implements support by treating each pass&\#x27;s caches as regular cache layers, avoiding new cache-management logic. The framework optimizes performance through fused message reads and controllers, batching GEMM operations, and generalizing existing fused kernels from Inkling 2 Small. For the variable-loop research checkpoint, vLLM exposes options to set the number of passes and whether to share KV caches across passes. Performance benchmarks show decode times ranging from 1.51ms \(1 pass, batch 1\) to 8.11ms \(3 passes, batch 32\), with accuracy matching the reference implementation across multiple evaluation benchmarks.

**「Takeaway」** vLLM demonstrates remarkable flexibility by implementing day-0 support for a complex looped model architecture while maintaining accuracy through careful optimization of memory management and kernel fusion techniques.
