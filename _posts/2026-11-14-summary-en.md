The issue was discovered by security researcher armcat and published on November 14, 2026, with the vulnerability reportedly related to Supabase configuration choices that prioritize ease of onboarding over security.

hackernews · armcat · Nov 14, 17:43 · [Discussion](https://news.ycombinator.com/item?id=50499017)

**「Background」** Lovable AI is an AI coding platform that enables users to build applications without traditional programming knowledge. These applications typically use Supabase, a backend-as-a-service provider that offers database and authentication functionality. The vulnerability stems from insecure database configurations where developers failed to implement proper access controls, allowing sensitive data including passport numbers and private messages to be accessible without authentication.

**「User Impact」** Affected users face potential identity theft and privacy violations as their passport details and private messages have been exposed to unauthorized access. Organizations using Lovable applications should immediately review their database security configurations and implement proper access controls to prevent further data exposure.

**「Community Perspectives」** The community debate centers on Supabase&\#x27;s responsibility in this vulnerability, with some noting that while the issue was supposedly fixed on October 30, existing projects may still have insecure defaults. Others argue that AI-generated applications create a new class of security risks as they are easily accessible targets requiring no sophisticated hacking knowledge, while highlighting the broader issue of insufficient security awareness among average users building applications.
